feat(catalogue): give the hand-typed UPG and WOG fuels their brand's code

The price import added in #1265 matches on brand_fuel_code alone, deliberately: these two brands
sell two distinct 95s and two distinct diesels, so a name- or category-based fallback would hand
both prices to whichever row the query returned first.

That is only safe once the rows it should match actually carry a code. None of them did - all eight
UPG and WOG fuels were typed in with brand_fuel_code = NULL - so a first run against the live sheets
would have created a second copy of every grade we already sell. Which is the duplicate #1265
deleted a route to prevent.

These two brands publish a token per grade, and on their own sites that token IS the name they show
their customers: UPG prints upg95 and EURO DIESEL, WOG prints ДП Євро5 and 95 Євро5-Е10. Our rows
were typed from those same pages, so their names already equal the codes. Hence an assignment rather
than a table of pairs - hardcoding an id-to-code list would be longer and wrong the moment a row is
renamed.

Scoped to upg and wog. KLO has no published fuel price list, so nothing here can say what its codes
are; those five rows stay uncoded until somebody with the price sheet decides. A fuel with no code
keeps working exactly as before - it is simply invisible to the import.

Verified against production data before writing it:

- the 5 rows that would be coded, each matching its brand's published token exactly
- KLO's 5 rows untouched
- 0 within-brand collisions on the code index, so the migration cannot half-apply
